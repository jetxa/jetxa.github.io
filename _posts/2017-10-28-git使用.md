## commit 
### 遗漏文件 或 修改commit信息
提交后发现忘记了暂存某些需要的修改，可以像下面这样操作
```bash
git commit -m 'initial commit'
git add forgotten_file
git commit --amend
```
最终你只会有一个提交——第二次提交将代替第一次提交的结果。

## 撤销
### add后撤销
```bash
git reset HEAD   撤销add状态
git reset HEAD file.md 撤销file.md 文件的add状态
```
### commit后想撤销
```bash
git reset --soft HEAD^   回退到add状态
git reset --mixed HEAD^ 撤销add 状态，默认
git reset --hard HEAD^ 删除代码的改动，不建议
```

### push后想撤销
建议push前确认，是否可以push
```bash
git log  查看日志，记录要回退到哪个版本
git reset --soft commit_id   本地先回退版本
git push --force  添加--force参数强制提交
```


## 设置和取消代理
``` bash
git config --global http.proxy 'socks5://127.0.0.1:1080'
git config --global https.proxy 'socks5://127.0.0.1:1080'
查看
git config --global -l
```

git push 错误
```bash
[remote rejected] master -> master(branch is currently checked out)
解决办法:在源仓库中修改.git文件夹中config文件,添加
[receive]
    denyCurrentBranch = ignore
```
    
## 初始化仓库
初始化远程仓库时最好使用 `git --bare init` 而不要使用 `git init`
* `git init` :一般是在本地进行git管理,可以看见源文件, 版本记录是在 .git 文件夹中
* `git init --bare` :一般是在远程服务器中进行创建的仓库,里面仅包含 本地仓库中 `.git`文件夹内的东西,看不到具体的文件,适合远程备份及协作开发

## 添加tag
```bash
git tag -a tagname <commit-hash-id>
```
标签不会提交到服务器,需要显式的操作
```bash
Git push origin init #将init标签提交到git服务器
Git push origin -tags #将本地所有的标签一次性提交到git服务器
```

## 切换tag
```bash
git checkout tagname
```

## 修改git commit 的编辑器
```bash
git config –global core.editor vim
```

## 指定 commit 时间
有时在迁移旧文章或笔记时，希望 commit 的时间是过去的时间，可以通过环境变量 `GIT_AUTHOR_DATE` 和 `GIT_COMMITTER_DATE` 来指定：
```bash
# 提交时指定特定时间
GIT_AUTHOR_DATE="2017-10-28T12:00:00+0800" GIT_COMMITTER_DATE="2017-10-28T12:00:00+0800" git commit -m "commit message"
```
